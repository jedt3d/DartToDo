Two later observations extend this list. The final `dnf inspect` run recognizes the root workspace configuration but marks all three child packages unresolved because `inspectProject` looks only for a package-local `.dart_tool/package_config.json` and lockfile. Flutter's real workspace resolution, locked setup replay, analysis, generation and tests pass using the root files. A next-round change should resolve the nearest owning workspace configuration/lockfile and identify the owning file in provenance, with ordinary-package and nested-workspace fixtures. The existing installed-source reader already searches ancestors; do not treat the inspection warning as an instruction to create conflicting child lockfiles.

Repeated catalog recording also overwrites reports/raw machine logs at a fixed case path. Wrapper attempt logs preserve command outcomes, but overwritten case payloads cannot be revalidated as historical evidence. The application runner now gives each release run a UTC/fingerprint directory and retains its input, case reports, raw machine logs, catalog snapshot and summary. A core tool enhancement should offer immutable run IDs and interrupted-run/resume semantics. Verify old artifacts stay unchanged after a later recording and keep partial interrupted runs distinct from complete validation.

App repairs such as semantic labels, target sizes, URL guards and explicit drag controls are already tested application changes. They justify examples and regression guidance; they do not by themselves validate any proposed tool patch. No matched B/C effect, cost saving, statistical significance, human rating or security certification is inferred from this list.

## Issue 9 observations · 18 November 2026

The stock native integration driver returned exit 0 after a timed-out test and printed “All tests passed” while the actual notification evidence was incomplete. The application’s dedicated notification and printing drivers now require explicit completed/permission/delivery or native-invocation/return fields as well as the integration test result. The next toolchain round should parse native framework results and domain assertions rather than treating process exit as sufficient. Retain negative timeout, missing-plugin and denied-permission controls.

Xcode 27.2 uses Device Hub at `/Applications/Xcode.app/Contents/Applications/DeviceHub.app`; the missing old Simulator application was not a missing simulator capability. Actual native permission prompts and lock-screen notification cards are accessible there. Native macOS print invocation also exposed a missing `com.apple.security.print` entitlement that widget channel-argument tests could not detect. Future native preflight should compare declared features with Debug and Release entitlements and observe the OS interface, while retaining sandbox protections.

Interactive native accessibility inspection can enable Flutter semantics during an integration test and produce an outstanding-handle assertion. A test harness should establish its accessibility mode before the test baseline; it must not suppress leak assertions or dispose handles owned by the OS. These are observed validation problems and proposed reusable checks, not a measured improvement to the sibling toolchain or a reason to change its historical benchmark evidence.
