# Microsoft To Do behavior reference

Research snapshot: 17 November 2026. Primary sources below establish documented behavior, not proof that the installed macOS release or every iOS release has identical controls. The main agent is independently inspecting the installed app. This document contains no real user tasks or private screenshots.

## Local feature matrix

| Feature | Documented behavior and source | Platform boundary and acceptance implication |
|---|---|---|
| Task lifecycle | Enter a title in the add field; Return/Enter appends the task. Selecting a task opens its editable title/details. Deletion is available in details; iOS supports a delete swipe. [Create/edit/delete](https://support.microsoft.com/en-us/todo/create-edit-delete-and-restore-tasks). | General To Do guidance; the page distinguishes mobile gestures and desktop bulk selection. Verify actual macOS and simulator input paths. |
| Completion | Completion can be reversed; completed items can be hidden. [Task accessibility guide](https://support.microsoft.com/en-us/accessibility/todo/use-a-screen-reader-to-work-with-tasks-in-to-do). | Guide has macOS and iOS sections. Keyboard/VoiceOver actions are platform-specific; do not infer them from Windows shortcuts. |
| Steps, importance, notes, tags | Steps retain a completed/total counter. Stars feed Important. Notes and hashtags provide additional organization. [Task detail features](https://support.microsoft.com/en-us/todo/add-steps-importance-notes-tags-and-categories-to-your-tasks). | The source separates all-platform content from web-only categories. Do not treat categories as proven macOS/iOS parity. |
| My Day and suggestions | Users add tasks directly or from other lists. Suggestions offer tasks to add. The nightly reset clears daily selection while preserving unfinished tasks, which become later suggestions. [My Day](https://support.microsoft.com/en-us/todo/my-day-and-suggestions). | Use the local calendar date, not a destructive task deletion or a fixed UTC day. Exact ranking of suggestions is not specified. |
| Due date/reminder/repeat | Planned contains scheduled work. Due choices include today, tomorrow, next week and custom date; reminders offer relative choices and custom date/time. Repeat options include daily, weekdays, weekly, monthly, yearly and custom. [Scheduling](https://support.microsoft.com/en-us/todo/add-due-dates-and-reminders-in-microsoft-to-do). | Generic documentation does not establish the installed app's exact presets, OS notification delivery, or recurrence arithmetic. Exercise selected native pickers and actual notifications separately. |
| Search and sort | Search examines tasks, steps, hashtags and notes. Sort choices include importance, due date, My Day, alphabetic order and creation date. [Sort/search](https://support.microsoft.com/en-us/todo/sort-and-search-in-lists). | Installed macOS menu may expose a subset per list. Search must reach steps/notes, not only task titles. |
| Lists and groups | Groups organize lists through drag/drop. Mobile also offers add/remove lists. Renaming and ungrouping are supported; ungrouping preserves the lists. [Organize lists](https://support.microsoft.com/en-us/todo/organize-your-lists). | Desktop uses context menus; mobile uses an overflow menu. An ungroup action must not cascade-delete list contents. |
| Themes | Lists offer colors and full-screen image backgrounds, including the Berlin tower theme. [Historical feature announcement](https://support.microsoft.com/en-us/todo/what-s-new-in-microsoft-to-do). | This is a historical announcement, not a current complete theme inventory. Use the installed reference for exact local assets/layout and record provenance. |
| Files | To Do's documented task attachment limit is 25 MB; several files can be attached, one at a time. [Outlook To Do documentation](https://support.microsoft.com/en-us/outlook/calendar/manage-tasks-with-to-do-in-outlook). | Source specifically covers Outlook surfaces. Installed macOS exposes Add File, but cross-platform size/open/save behavior still needs trial verification. Keep file names/bytes local and validate inputs. |
| Keyboard | Microsoft publishes Ctrl-based shortcuts for Windows. The accessibility guide documents Command+F on macOS. [Windows shortcuts](https://support.microsoft.com/en-us/todo/using-keyboard-shortcuts-in-microsoft-to-do), [platform guide](https://support.microsoft.com/en-us/accessibility/todo/use-a-screen-reader-to-work-with-tasks-in-to-do). | Do not mechanically claim all Ctrl shortcuts map to Command. Inspect installed menus and test actual implemented shortcuts. |
| Smart date recognition | Microsoft explicitly documents Windows 2.66+ recognition and iOS date/reminder suggestions. [Smart recognition](https://support.microsoft.com/en-us/todo/smart-due-date-reminder-recognition-in-microsoft-to-do). | macOS support is not established by this source. Exact parsing, language support and suggestion behavior remain unknown for the installed release. |
| Delete recovery | Microsoft task/list recovery uses Outlook/Exchange Deleted Items. [Task recovery](https://support.microsoft.com/en-us/todo/create-edit-delete-and-restore-tasks), [list recovery](https://support.microsoft.com/en-us/todo/delete-and-restore-lists). | That cloud recovery path is excluded by the brief. A local undo/restore mechanism is a deliberate substitute; test persistence and restoration rather than labeling it identical. |

## Account integration boundary

The brief excludes Microsoft account integration and limits storage to the current local user. Sharing invitations, assigning work to other members, Flagged Email, Outlook/Exchange recovery, and cloud synchronization therefore cannot be implemented as live Microsoft services. Assignment requires a shared-list member in Microsoft's [task guide](https://support.microsoft.com/en-us/accessibility/todo/use-a-screen-reader-to-work-with-tasks-in-to-do). Preserve the local core workflow and make any account-dependent omissions explicit in final scope. Do not display invented mail/tasks or imply integration is active.

The dedicated Serverpod/PostgreSQL service is the requested local persistence architecture. Keeping one user's data locally is distinct from proving OS-level isolation against other processes or users; network binding and access behavior require separate checks.

## Unresolved parity questions

- The public scheduling page does not define the next recurrence when completing an overdue task, month-end/leap-day arithmetic, custom weekday rules, or reminder-time preservation. Declare deterministic local behavior and test boundaries; direct reference observation is needed before exact-parity claims.
- Public sources do not fully specify drag ordering between all smart/custom lists, suggestion ranking, duplicate/copy details, undo history, autosave timing, print layout, or all settings. Capture the installed controls before choosing behavior.
- Native macOS references do not establish iPhone/iPad visual fidelity. Simulator builds and launches prove compatibility only when actually run; they do not prove equivalence to an uninspected iOS source app.
- No Figma reference was supplied. Token consistency, screenshot comparison, Flutter goldens, accessibility, Widgetbook inventory and runtime coverage are separate evidence categories.

## Independent acceptance probes

Use synthetic test data: create a task in a custom list, rename it, add two steps and a searchable note, complete one step, star it, set a date/reminder, move it, complete/uncomplete it, and reopen the application. Verify Important/Planned reflect stored state and search reaches the step/note. Add it to My Day, advance an injected local clock past midnight, and verify the task persists outside today's selection. Create a group, add the list, ungroup it, and verify the list/tasks survive. Exercise recurrence with explicit worked month/year examples and record the local contract. Delete/undo and restart to verify recoverability. Run real database and generated-client checks independently of widget tests.

These are proposed probes, not executed results. Human ratings, human completion time, exact visual fidelity, and model-efficiency improvement remain unmeasured.
