## What is already better

The app now catches more typing/async/resource mistakes during analysis, includes the backend launcher in its format check, and has sixteen additional regression tests across attachment UI and photo transport. The coverage gains came from exercising and asserting behavior; denominators were kept explicit instead of excluding missed code. Coverage still measures execution, not assertion quality or complete correctness.

The workflow now distinguishes a failed application check from a missing prerequisite, a passing subset from an unrun test, and a widget mapping from actual named runtime evidence. Findings become issues before fixes, with source-bound validation, reviewed PRs and closure after merge. Clean checks and conditional non-adoption decisions receive reports without invented defect tickets. Local raw evidence remains ignored; published reports and GitHub carry the reviewable result. Reviews in Rounds 7–10 are author self-reviews, not independent approval.

For everyday work, run analysis/formatting and affected tests after coherent changes and before PRs. Refresh declaration/state recordings after production Dart edits. Measure coverage deliberately with the same declared populations; investigate meaningful missed behavior. Run native checks when platform behavior changes or making a native claim, using the documented isolated test backend and explicit target. The broad development runner retains its existing defaults; selecting a URL is not itself proof of database isolation. The [quality guide](README.md) is the operating reference.

## Useful next improvements, without starting deferred rounds

- Use Round 7's widget-builder/layout/parser watchlist to focus review when changing those areas. Extract a helper only for a clear responsibility with behavior preserved; a high ranking alone is not a defect or reason for a broad refactor.
- Investigate concrete uncovered startup/domain behavior before adding further tests. Frontend `main.dart`/`app_entry.dart` and backend `bin/main.dart` were absent from their coverage traces; the photo endpoint wrapper remained 0/3. Keep unmeasured files visible and choose a threshold only after agreeing on the denominator and purpose.
- Resolve the actual macOS build/foreground diagnostics in issue #28 through a scoped investigation. The native core pass does not close notification activation or human visual acceptance in issue #9.
- Reconsider an app-specific lint only if a repeated, precisely detectable violation emerges that existing rules/centralized code/tests do not adequately address. Specify false positives and rule tests before adopting a framework.

No new complexity or coverage gate was installed. **Round 11 (goldens/visual regression), Round 12 (DevTools profiling), and Round 13 (CI gates/review automation) remain deferred.** No approved golden/performance baseline or CI protection was created; analyzer CI remains tracked in [issue #13](https://github.com/jedt3d/DartToDo/issues/13). Physical printing remains outside the authorized checks. Existing human visual approval and macOS notification-activation gaps remain explicit in [issue #9](https://github.com/jedt3d/DartToDo/issues/9).
